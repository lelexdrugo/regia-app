# The app's frontend

Svelte 5, TypeScript and Vite, as a single-page app without SvelteKit (ADR 0001 §13). It runs in the app's webview, under the CSP and the capability of `app/src-tauri`, and talks to the core only through the app's commands.

## Build it before Cargo

`tauri::generate_context!` embeds `dist/` when the app crate compiles, so every `cargo build` or `cargo test` of the workspace needs it. Node 22 or later:

```sh
cd app/ui
npm ci --ignore-scripts
npm run build      # writes dist/
npm run check      # types and Svelte's compile-time checks, warnings included
npm run prove      # the harness and its proofs, below
```

Without `dist/index.html` the app's `build.rs` stops with this instruction. After changing the frontend, `npm run build` again: the next `cargo build` embeds the new files. There is no development server: the CSP is enforced only on the embedded files, so they are what the tests run on (threat model §3.5).

Dependencies install no scripts (`.npmrc`, threat model V23). A new dependency is a choice to justify, with its licence: the webview runs it with the app's permissions. The harness and the proofs add none.

## Text from others

Titles, documents, comments and transcripts are written by people and by agents, and arrive raw from the tracker. They never pass through the catalog, and they reach the DOM only as text:

- the core normalizes them and parses markdown into a closed tree (`regia-core`'s `text`, `markdown` and `link` modules); `src/lib/content/` renders the tree, element by element, with no attribute from the content, and a link is a button that calls back with the URL the core checked (threat model §3.7);
- an element that holds such text carries `data-raw`, so the catalog proof can tell it from the catalog's strings;
- V08: no line of `src/` or `index.html` may name `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `DOMParser`, `eval`, `Function`, a timer given a string, `{@html}` or the newer APIs that parse HTML, unless it gives its reason on the same line (`V08: <reason>`). `app/src-tauri/tests/security.rs` checks it in every `cargo test`; the one use is `smoke.ts`'s probe of the CSP.

## The harness and the proofs

`npm run prove` builds the harness and runs ten proofs: one in Node, the others in one headless Chrome. Each checks the app, then a negative control of its own, and fails if the app fails or if the control passes. They run in CI, in the Linux job, with the runner's Chrome.

- The **harness** (`harness/`, built by `vite.harness.config.ts` into the workspace's `target/ui-harness`, never into `dist/`) mounts the app's own components on fixtures: `#/<view>?data=<state>&lang=<it|en|xx>`. `prove/serve.js` serves it with `tauri.conf.json`'s policy, with `connect-src 'none'` for the IPC it does not have. `xx` is a pseudo-locale (`harness/pseudo.ts`): each message wrapped in ⟦ ⟧ and 40% longer.
- **contrast** (`prove/contrast.js`): first, `src/tokens.css` is still the dossier's file, by its SHA-256; then the 30 pairs of the UX prototype, in the design system's three directions. Controls: one digit changed in the copy, one token made fainter.
- **moviola** (`prove/moviola.js`, in Node, which runs the TypeScript with its types stripped): the moviola's model, layout and scene against the prototype's viewer, on `harness/moviola.json`: the same lanes in the same order, the same nodes with their rings and badges, the same columns at three sizes, with and without a window, the same time scale with its joints, the rings' places. Then what the prototype has no answer for, by invariants: the labels (#489) on a crowded lane, their plates where they are drawn, on the node's left near the stage's right edge included, covering neither one another nor the lanes' names, and by rank, every turning point left out blocked by one of its rank or higher; the level of detail (#489) on x10's synthetic story, at six zooms from the whole stage up, every milestone in exactly one group of its lane, the groups in view holding every milestone in view, each edge between two groups one group edge; the camera, the lanes' envelopes, the days, the portfolio's order, a catalog id for every kind and health. Then the frame of every milestone (#487) against the one the prototype draws (`disegnaL3`), section by section, every `#N` at the prototype's address; the chat package against `pacchetto`, byte for byte with the prototype's words, the long one shortened included; the search by invariants. Then the overview (#598): the tape's and the strip's scale against the prototype's on a dense story, within a pixel, and on alpha, a sparse one, the story over at least half the tape; the filters (`visibileFiltri`) on every case and setting, the state at a date (`statoAlla`), the directions' cards (`disegnaL1`) and the time window (`impostaFinestra`) against the prototype's answers. Controls: the lanes in the order of the directions' file, a column moved by one pixel, a label on every turning point, the renderer spike's picker (overlapping plates, and a lower rank before a higher one), the spike's level of detail (none of x10's milestones drawn at its overview), a frame with the next milestone's sidecar, `#N` split without the look-ahead, `#1` looked for in the title, the references dropped before the summary is shortened, the prototype's tape on alpha, joints always as wide as twelve hours on the dense story, a filter deaf to the kinds hidden, a state at a date that counts the moment at the instant after it.
- **frame** (`prove/frame.js`): the frame of a moment (#487) in Chrome. The address opens it on the stage; the summary first, and the why first when there is none; a `#N` of each of the three linked sections points at the prototype's issue; a text with `<` stays text; a moment with reviews shows its checks, defects and models, a task with no session and no tokens says so; «Copy for chat» selects its five lines; «Then», the steps and the close button move the stage's choice. Controls: the links' check on notes refused (`notes=fail`), the summary's check on a moment without one.
- **stage** (`prove/stage.js`): the moviola's Canvas on alpha's lanes. The backing store at density 1 and 2; each direction redrawn in its tokens, background and marks, without a reload (#486, Acceptance 3); the timecode in the DOM as the catalog's `date-day-time` of its instant; the arrows, Home, End and Esc; a click on a node; the wheel, a drag, 0; the playhead dragged on the stage, and a click on the tape; the overview (#598): alpha's story over at least half the tape, measured on the canvas's pixels at density 2; a kind hidden, its moment almost gone and out of the pointer's reach, «Clear the filters» bringing it back; the project at the playhead as `statoAlla` says it at three places; a window drawn on the strip shown by the stage, a double click for the whole story; a direction chosen, its moments listed and the other lanes dimmed; the level of detail (#489) on `#/moviola/dense`, the wheel taking it to the whole stage: the stage keeps its size, the line under it says how many groups and moments are in view, each group's mark is in its kind's ink where lod.ts puts it, measured on the canvas's pixels, and a click on a group of several opens it at the zoom of detail; the portfolio, each project with its health and its last milestone (Acceptance 2). Controls: a stage deaf to the direction (`theme=fixed`), the prototype's timecode, and the groups with every kind hidden.
- **catalog** (`prove/catalog.js`): every view and state in `xx`, with no text outside the catalog or `data-raw`. Control: a string written in the code. It also counts, as information, the messages no source names yet.
- **limits** (`prove/limits.js`): every view and state, in it, en and xx, at 1440×900, 1024×700 and 720×450, against content outside the window, cut controls, text squeezed into a column, raw values, parameters left in braces and markup that became elements. Control: a page with three of those.
- **v07** (`prove/v07.js`): the core's hostile corpus through the app's renderer, judged by `src/lib/v07.ts`, which `app-smoke` also runs on each engine; the browser and the server witness every request. Control: the same corpus through a deliberately unsafe renderer.
- **language** (`prove/language.js`): on the brief of 1,284 tasks scrolled far down, the arrow keys change the sidebar's language and back, and the page keeps its place: no reload or navigation, the same address, the same rows where they were on screen, the focus on the language chosen, the words of the other language, the choice saved. Control: the change made as a reload.
- **keyboard** (`prove/keyboard.js`): the shell's keys, pressed as a keyboard sends them and read in Chrome's accessibility tree, by role and name: `g` and a letter, `?` and Esc with the focus coming back, the help's words (#439/D31) in both languages, the Tab order from the skip link with a ring on every stop, the settings with the arrow keys, `prefers-reduced-motion`, the sidebar's quota in words (#439/D29), the help's part on the moviola, and the moviola's search as the UX prototype's prove-keyboard has it: `/`, typing, Enter, `,`, Esc, «Clear the filters», a `#N`, leaving the screen, ← on the range (#487); then the filters and the panel at the playhead (#598): Tab from the search to the kinds and Space to hide one, `.` within the filters, the advanced mode and a lane by the arrow keys and back, «Clear the filters», Home on the range and the panel's last moment by Tab and Enter. Controls: the control page, which has none of it, the prototype's glossary and quota, and `/` on the moviola's portfolio.
- **brief** (`prove/brief.js`): the brief against `harness/brief.json`. Each group in the fixture's order, which no field gives, and the core's lists back from the rows' places; the due marks and the measures in both languages, a far date and a task that unblocks nothing left unmarked, as in the CLI's text; each warning of the controller with its own cause (#439/D16); a note in the place of each section `not_ported` names, and none for the others; every block's state; the marker; Retry; hostile text as text. Controls: the fixture sorted by number (`sort=number`, a view that orders), the prototype's stopped line with its one cause (`#/stopped`), the brief without `not_ported` (`ported=all`, a view that shows an absence), and the control page, with no marker.

The moviola's quick check of the time per frame runs by hand, never in `npm run prove`: a headless browser without GPU says nothing about frames. `node prove/bench.mjs --engine webview2 --host <a WebView2 app> --out <folder>` serves the harness as the proofs do and opens `#/bench?scale=1` and `?scale=10` (`harness/bench.ts`: the renderer spike's harness, commit 84871ea, on the product's stage and a synthetic timeline in the shape of the real stores, `harness/synthetic.ts`), then takes alpha's lanes in the three directions, the portfolio and the x10 stage. A WebView2 app that lets its page navigate, started with `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` opening the DevTools on a port, is the host: the spike's `moviola-bench.exe` is one. `--engine edge` or `chrome` use the browser in a window, with its GPU; `--engine headless` takes only the screenshots.

`CHROME_PATH` picks the browser, which runs with `--disable-ipc-flooding-protection`: the proofs move the harness more than 200 times in 10 s, and Chrome would then ignore the address without a word; otherwise `prove/cdp.js` looks where runners and desktops keep Chrome or Chromium, and tries a desktop Edge last, since an Edge that is already open can take the launch over. `node prove/index.js limits` runs one proof.

The fixtures are synthetic. `harness/brief.json` is written by hand in the shape of `ipc.rs`'s `BriefView`, within the core's caps (200 characters, one line): `demo` and `worst` fill every block, the controller's, the dossiers' and the outside-tracker's included, which the core does not read yet; `one` and `empty` name them in `not_ported`, as the app's brief does today; `done` holds what the app decided today, which only #477 will record. The `huge` brief and the `huge` document are built from it in `harness/main.ts`. In `harness/documents.json` the markdown is written by hand and the trees are the core's, as in `harness/corpus.json`, which comes from the core's corpus. After changing either, or the core's parser: `cargo test -p regia-app -- --ignored write_harness`. A test fails while they are stale. `harness/moviola.json` holds the moviola's fixtures and the prototype's answers on them: fixtures/moviola's portfolio and timelines in the core's shape, and the case of the dossier's `test_moviola_viewer.py`. It is recorded from the prototype's viewer by `REGIA_HOME=<the dossier> node prove/moviola-record.mjs`, the prototype's side, which speaks its keys and so is a `.mjs`, outside the guard against Italian names. Since #487 it also holds the sidecars in the core's shape, and for every milestone the frame the prototype draws, read back from a small DOM, and its chat package; the case `frame`, written there by hand, has a `#N` in each linked section, markup in a text and a package too long to fit. In the harness `#/moviola?data=demo` is that portfolio, `empty`, `loading` and `error` its other states, and `#/moviola/<id>` a project's lanes; gamma has none, `dense` is x10's synthetic story (`harness/synthetic.ts`, the quick check's generator), reached by its address only, and an unknown id is refused as the app's command refuses it. `#/moviola/<id>/<milestone>` opens a moment, `?q=` a search, `?filters=advanced`, `?hide=<kind>,…` and `?lane=<id>` the filters and a direction (#598); `notes=fail` refuses the sidecars and `notes=wait` never answers. Since #598 the file also holds, under keys of their own, the prototype's tape and strip on a dense story and on the fixtures (`tape`), its filters (`filters`), its state at a date (`states`), its directions' cards (`lanes`) and its time windows (`windows`).

A new view adds its routes to `harness/main.ts` and `prove/views.js`. The sections are the whole shell on one fixture (`data`, `lang`, `dir`, `density`, `save=fail`, `help=1`, `quota=<used>`, and for the brief proof's controls `sort=number` and `ported=all`): the shell's own moves keep it mounted, and only the current mount may say it has drawn.

|---|---|

| `src/lib/ipc.ts` | One hand-written wrapper per app command |
| `src/lib/i18n.ts` | Fluent, over the `.ftl` files of `crates/regia-i18n/locales/`, read at build time: the CSP admits no fetch |
| `src/lib/content/` | The renderer of the core's markdown tree |
| `src/lib/smoke.ts`, `src/lib/v07.ts` | Test only: what `app-smoke` checks on each engine (rendering, V07 on the DOM, CSP, navigation, ACL, CSS features) |
| `src/tokens.css`, `src/fonts/` | The design system's tokens, the dossier's `docs/app/design-system/tokens.css` at 38c87dc unchanged under a header, and the faces it names with their licences. To realign: copy the file again and update the hash in `prove/contrast.js` |
| `src/App.svelte` | The shell: the skip link, the sidebar (`src/shell/`), the section the address names (`src/lib/route.ts`), the keys and the help (`src/lib/glossary.ts`) |
| `src/screens/` | The screens this version has: the brief, the moviola, the settings; the other sections say their screen comes later |
| `src/screens/Brief.svelte`, `src/screens/brief/`, `src/lib/brief.ts` | The brief: the queue's groups in the core's order (the view sorts nothing: `lib/brief.ts` only splits the tasks that need a session from the rest, as the CLI's text does), each block's state, the controller's warnings with their own causes. `data-brief` on its screen is `loading` until the core's answer is in the DOM, then `ready` or `failed`: the marker of the first brief on screen, for the dossier's T2 milestone. Each row carries `data-section`, `data-number` and `data-rank`, its list and place in the core's brief, which `app-smoke` reads back (`lib/smoke.ts`) |
| `src/screens/Moviola.svelte`, `src/screens/moviola/` | The moviola, read only: the portfolio of `list_projects` at `#/moviola` (`Projects.svelte`, each project's health and last milestone, the prototype's L0), a project's lanes at `#/moviola/<id>` (`Timeline.svelte`: the search, the Canvas, the transport, the moment chosen; since #598 the filters, `Filters.svelte`, the strip «time window» above the stage, the project at the playhead under it, `AtDate.svelte`, and the directions, `Directions.svelte`, the prototype's L1, while no moment is open), and beside them the frame of the moment chosen (`Frame.svelte`, #487: the summary, the why, how it got there, the references, «Copy for chat»), at `#/moviola/<id>/<milestone>` when the address names one. `data-moviola` on the screen is `loading`, then `ready` or `failed`; the timecode's `<output>` carries its instant in `data-t`; the line under the stage, `#moviola-groups`, says what the groups in view hold when the stage is zoomed out (#489), its numbers in `data-groups`, and stays there empty so the stage keeps its size; the frame carries its moment in `data-moment` and the state of its sidecar in `data-frame` |

| `src/lib/look.ts` | The direction and the density on `<html>`. The app serves `index.html` with the saved ones already there (`app/src-tauri/src/settings.rs`, the file `interface.toml` in the configuration folder), so the first paint is in them |

Every language's catalog is in the bundle: about 25 kB of `.ftl` each, 8 kB gzipped. Importing only the active one would save that much, for an extra chunk to load before the first paint and another whenever the language changes. With a third language it becomes worth it.
